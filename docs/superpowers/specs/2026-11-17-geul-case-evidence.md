## 01. AI가 명세를 고치지 못하게 작업 공간을 셋으로 나누기 (묶음: AI와 일하는 구조)
- 문제 [원본]: 혼자 세 역할을 맡으면, 명세가 불편할 때 구현하던 AI가 명세를 고쳐 버릴 수 있습니다.
- 원인 [저장소]: 처음에는 사람이 둘이라 문서와 코드의 담당이 갈려 서로 막아 줬지만, 혼자 세 역할을 맡게 되면서 그 구조가 사라졌습니다. 또 대화가 길어질수록 AI가 앞에서 정한 금지 사항을 놓쳤습니다. 출처: docs/adr/0008(결정 근거), 원본 TO-BE의 마지막 문장
- 해결 [원본]: 작업 공간을 기획, 백엔드, 프론트엔드 셋으로 나누고, 프론트엔드 세션은 기획 문서를 고치지 못하게 했습니다. 명세가 틀렸다고 보이면 기획 세션에서 따로 고칩니다. 할 일 체크박스 하나를 한 세션 분량으로 정해, 끝나면 커밋하고 새 세션을 띄웠습니다.
- 확인한 방법 [저장소]: 명세를 바꿀 때는 기획 세션에서 "명세 변경:"으로 시작하는 커밋으로만 고쳤습니다(예: 선택지 삭제 0d58658). 출처: 커밋 기록
- 결과 [확인 필요]: 원본에 결과 문장이 없다. "24일 동안 혼자 세 역할로 기획부터 배포까지 마쳤습니다"(원본 개요의 사실)로 써도 되는지 확인
- AI 표시: 이 사례 자체가 AI와 일하는 방식이라 "AI 도구(Claude Code)" 이름이 본문에 있다

## 02. 화면 문구가 기준 문서와 어긋나면 CI가 막게 하기 (묶음: AI와 일하는 구조)
- 문제 [원본]: 나흘 동안 화면 문구가 기준 문서와 어긋난 일이 네 번 있었고, 그중 둘은 배포까지 나갔습니다.
- 원인 [저장소]: 네 번 모두 사람이 우연히 찾았고, 다음에도 사람이 찾는다는 보장이 없었습니다. 그중 하나는 일주일 동안 화면에 떠 있었습니다. 출처: 커밋 8001dd0
- 해결 [원본]: 화면에 나가는 문장은 문구 기준 문서(docs/문구.md) 하나에서만 가져오게 하고, 코드의 문구가 문서에 없으면 CI가 막도록 검사(make check-copy)를 붙였습니다.
- 확인한 방법 [저장소]: 문서 전체와 대조하면 문서가 "버린 문장"으로 인용해 둔 옛 문구까지 통과해 버리는 것을 실제로 확인하고, 대조 범위를 문서의 표와 인용 칸으로 좁혔습니다. 출처: 커밋 8001dd0("전체 대조로는 errors.py의 옛 RATE_LIMITED가 통과했다")
- 결과 [저장소]: 이후 문구를 코드에 직접 적은 곳을 검사가 잡아, 문서에서 읽도록 고친 기록이 이어집니다(예: d78bf72, 1100654).
- AI 표시 [확인 필요]: 검사 스크립트를 AI 도구로 작성했는지. 저장소 코드는 대부분 AI 도구로 만들었다(원본 개요)

## 03. AI가 요청하지 않은 화면 변경을 찾아 되돌리기 (묶음: AI와 일하는 구조)
- 문제 [원본]: AI가 제 지시와 자기 판단을 한 커밋에 묶으면서, 요청하지 않은 접속 코드 표시 변경(702812 → 702 812)이 섞여 들어갔습니다.
- 원인 [저장소]: 커밋 첫 줄을 "사용자 지시"로 열고 그 안에 AI의 판단을 함께 담으면, 나중에 어디까지가 지시였는지 가를 수 없었습니다. 출처: 커밋 5b15bf2 메시지
- 해결 [원본]: 화면에서 발견해 되돌리고, 지시한 내용과 AI가 스스로 정한 내용을 커밋에서 구분하게 했습니다.
- 확인한 방법 [저장소]: 화면 사진 두 장을 비교해 "여백이 왜 생겼나, 내가 요청했나"를 물어 드러났습니다. 출처: 커밋 5b15bf2 메시지
- 결과 [저장소]: 커밋마다 "사용자 지시"(36건)와 "대표 결정"(5건)을 표시해, 어느 변경이 누구의 결정인지 기록에 남겼습니다. 출처: git log 집계
  - 개수 표기 [확인 필요]: 프로젝트가 끝나 더 늘지 않는 숫자라 정확히 쓰려고 한다. 대략으로 바꿀지 확인

## 04. 아이가 모르는 낱말을 아는 사물로 풀어 쓰기 (묶음: 화면을 보고 판단한 일)
- 문제 [원본]: 이야기 뼈대에 "태엽새"라는 말이 있었는데, 만든 저도 바로 떠올리지 못했습니다.
  - [확인 필요]: 커밋 a3f673f에는 "「태엽새」가 대표에게 되물림당했다"고 적혀 있다. 원본 문장(만든 저도 바로 떠올리지 못했다) 그대로 둘지 확인
- 원인 [저장소]: 아이가 읽는 글 중 가장 넓은 면인 AI의 이야기 글에 어휘 기준이 없었습니다. 출처: 커밋 8b04bbe
- 해결 [원본]: 다른 낯선 말로 바꾸지 않고 아이가 아는 사물의 모양과 움직임으로 풀어 쓰기로 했고, AI가 이야기를 지을 때 받는 지시문에도 같은 원칙을 넣었습니다.
- 확인한 방법 [확인 필요]: 저장소에서 따로 확인한 기록을 찾지 못했다. 원칙 문서(커밋 02a273f "되물음이 곧 결함이다")는 있다. 실제로 어떻게 확인했는지 알려 주거나, 이 칸을 "되물음이 생기면 그 낱말이 결함이라는 원칙을 세웠다"로 쓸지 확인
- 결과 [원본]: "커다란 태엽새" → "등에 달린 톱니바퀴가 거꾸로 도는 커다란 새 인형"
- AI 표시: AI의 지시문을 고친 사례라 본문에 AI가 나온다

## 05. 저장 규칙은 맞아도 빈 책이 보이던 버튼 고치기 (묶음: 화면을 보고 판단한 일)
- 문제 [원본]: 글을 쓴 직후 "내 책 펼치기"를 누르면 빈 책이 보였습니다.
- 원인 [저장소]: 본편은 이야기를 완결해야 책 한 장이 되는 저장 규칙이라, 첫 글을 쓴 시점에는 책이 0쪽이었습니다. 저장 규칙은 의도대로였고, 화면이 그 사실을 말하지 않은 것이 문제였습니다. 출처: 커밋 0c34a4f
- 해결 [원본+저장소]: 책이 비어 있으면 버튼을 보여 주지 않고, "이야기를 완성하면 책에 담겨"라는 안내를 책이 비어 있는 동안 계속 보이게 했습니다. 출처: 커밋 0c34a4f, 4a5de38
- 확인한 방법 [저장소]: 데이터베이스로 챕터 상태(10턴 중 1턴, 완결 전)를 확인해 원인을 좁혔고, 390, 360, 320px 화면 폭에서 글 쓰는 칸과 보내기 버튼이 잘리지 않는지 재서 확인했습니다. 출처: 커밋 0c34a4f
- 결과 [저장소]: 저장 규칙은 그대로 두고, 아이가 빈 책을 보는 일이 없어졌습니다. 이때 남긴 판단 "내부 저장 규칙이 맞더라도 사용자 경험은 잘못되어 있습니다"(커밋 0c34a4f에 사용자 말 그대로 기록)
- AI 표시 [확인 필요]: 코드는 AI 도구로 고쳤고 발견과 판단은 본인

## 06. AI 선택지를 없애고 직접 쓰기만 남기기 (묶음: 화면을 보고 판단한 일)
- 문제 [원본]: AI가 쓴 선택지만 눌러도 이야기가 끝까지 가서, 책에 아이의 글이 남지 않을 수 있었습니다.
- 원인 [저장소]: 선택지 문장은 아이의 글이 아니라 책에서 빠지므로, 직접 쓴 턴이 없으면 책 본문이 비었습니다. "아이가 직접 쓴 문장으로 모험이 진행되고 그 글이 책에 남는다"는 서비스 목표와 어긋나는 길이 열려 있었습니다. 출처: 커밋 0d58658, docs/adr/0017
- 해결 [원본+저장소]: 선택지를 없애고 직접 쓰기만 남겼습니다. 서버도 선택지로 진행하려는 요청을 거절하게 했습니다(422). 출처: docs/adr/0017, 커밋 0d58658
- 확인한 방법 [저장소]: 직접 쓰지 않은 요청은 챕터를 보기 전에 422로 거절하는지 서버 테스트로 확인했습니다. 출처: api/tests/test_stage1_contract.py 80행
- 결과 [원본]: 책에는 아이가 직접 쓴 문장만 남습니다. ([확인 필요]: 원본 문장을 결과로 줄인 것)
